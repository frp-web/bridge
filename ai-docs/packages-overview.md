# core

## FrpBridge 类职责
- 作为核心业务入口，负责协调 frp 客户端与服务端配置的全生命周期。
- 统一封装底层文件操作、网络请求等实现细节，为上层调用者提供稳定的 API。

## 服务进程控制
- 提供 `start` 方法，在准备配置与可执行文件后启动 frp 服务进程，并监听运行状态。
- 提供 `stop` 方法，负责优雅地终止 frp 服务进程，并在必要时清理临时资源。

## 可执行文件管理
- `downloadFrpBinary`：下载指定平台的 frp 可执行程序，处理版本号解析与存储目录的约定。
- `updateFrpBinary`：检查本地版本并触发更新，必要时保留旧版本以便快速回滚。

## 配置维护
- `updateConfig`：更新全局配置文件，支持增量写入与校验以防止配置损坏。
- `backupConfig`：备份现有配置，保留多份历史快照，便于在异常时恢复。

## 节点管理
- `addNode` / `updateNode` / `removeNode` / `getNode`：针对节点信息提供新增、删除、修改、查询的封装，本质上是按节点维度更新配置条目。
- 维护节点与其关联隧道的引用关系，确保配置一致性。

## 隧道管理
- `addTunnel` / `updateTunnel` / `removeTunnel` / `getTunnel`：提供隧道（Proxy）层面的增删改查接口，复用底层配置更新逻辑。
- 针对功能差异（TCP、UDP、HTTP 等）预留参数校验与模板化支持。

# cli

## 脚手架定位
- 面向最终用户，提供命令行入口以调用 `core` 中的能力。
- 可以在其他项目中作为依赖引入，也可独立安装为全局命令行工具。

## 命令封装
- 将 `FrpBridge` 的常用方法映射为子命令，如下载/更新可执行文件、节点与隧道管理等。
- 统一解析命令参数与交互流程，向用户输出友好的提示与错误信息。

## 生态集成
- 通过 `cac` 等 CLI 工具库实现命令注册、帮助信息与自动补全。
- 预留与后续插件、模板工程对接的接口，便于扩展。

# frp-bridge

## 包装与导出
- 聚合 `core` 与 `types`，对外暴露关键类、类型与辅助函数。
- 作为外部应用的首选入口，屏蔽内部包结构的细节变更。

## 使用场景
- 供第三方应用快速引入 `FrpBridge` 能力，无需关心底层依赖的安装顺序。
- 统一版本号与发布节奏，确保 CLI、核心库与类型定义在同一版本体系内协同工作。

# types

## 类型集合
- 根据 frp 官方文档整理客户端与服务端的配置类型，覆盖认证、网络、日志等关键字段。
- 提供 `client`、`server`、`common` 模块的聚合导出，便于按需引用。

## 与 core 的协同
- 为 `FrpBridge` 方法提供强类型签名，约束配置更新与节点/隧道管理的参数格式。
- 支持未来在 CLI 或其他工具中进行静态校验，减少运行时错误。
